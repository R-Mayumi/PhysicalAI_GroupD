# 日本語音声でGo2を操作する

Go2のカメラ・音声・LiDARなどを内部PCの変更なしで外部から利用する方法と実機の確認結果は、[外部プログラム利用機能の調査資料](docs/Go2_外部プログラム利用機能調査.md)にまとめています。

Whisperで音声を日本語のテキストにし、OllamaでGo2への指示に分類します。Pythonが速度と時間を決め、公式SDKのDDS通信でGo2に送信します。WebRTCのデバイスキーは使いません。

音声操作の自作コードは `go2_voice.py` の1ファイルです。以前のデモやヘルパーファイルは読み込みません。カメラ表示は別の `make_code/go2_camera.py` で実行します。

## LiDARを使ったキー操作

`go2_teleop.py` はUbuntu上で操作し、Go2の内蔵LiDARと運動状態を有線DDSで受信します。Spaceを押しながら方向キーを1つ押している間だけ速度指令を送ります。

| キー | 動作 |
|---|---|
| `Space` + `W` / `S` | 前進 / 後退 |
| `Space` + `A` / `D` | 左並進 / 右並進 |
| `Space` + `Q` / `E` | 左旋回 / 右旋回 |
| `Esc` | 停止して終了 |

キーを離す、障害物や未観測域が進行先にある、点群や運動状態が古い、のいずれかで速度をゼロにし、移動中なら `StopMove` も要求します。停止後はSpaceと方向キーをすべて離してから再入力します。並進は0.08 m/s、旋回は0.15 rad/sです。既存の開始位置と累積並進指令の25cm制限を使います。キー操作と音声操作は同一Linuxホストで同時に起動できません。

### 実機の設定と読み取り確認

1. Go2を有線接続し、状態コードが0で、平坦な床の上に立っていることを確認します。調査時のコード `1001` が現在も出る場合、キー操作は開始できません。
2. `docs/go2_lidar_calibration.example.json` を `go2_lidar_calibration.json` にコピーし、実機の値に合わせます。`lidar_xyz_m` は機体原点から見たセンサー原点、`lidar_rpy_rad` は点群座標から機体座標への姿勢（Xロール、Yピッチ、Zヨー）です。機体の+Xが前、+Yが左、+Zが上です。`ground_z_m` は立位での機体原点に対する平坦な床の高さです。サンプルの取付値は公式URDFの `radar_joint`、床面値は仮値です。実際の `utlidar_lidar` 座標に適合するか、床と位置が分かっている障害物を前後左右に置き、点群表示と照合してください。 [公式URDF](https://github.com/unitreerobotics/unitree_ros/blob/master/robots/go2_description/urdf/go2_description.urdf) [公式RViz手順](https://github.com/unitreerobotics/unitree_ros2#rviz)
3. 次の診断で点群受信、自機点数、床面と障害物の格子数、6方向の判定を確認します。Go2への動作指令は送信しません。

```bash
.venv/bin/python go2_teleop.py --check --calibration go2_lidar_calibration.json
```

障害物のない場所と、進行先に障害物を置いた状態を静止した機体で比較します。背面などで床点が不足すると、その方向の指令は停止になります。実機でキー操作を試すときは、リモコンで停止できる状態を確保し、開けた床でキー解放時の制動距離と停止時間を各方向で測ってください。

```bash
ls -l /dev/input/by-id/*-event-kbd
.venv/bin/python go2_teleop.py --drive --calibration go2_lidar_calibration.json \
  --keyboard /dev/input/by-id/対象キーボード-event-kbd
```

コマンド中のデバイス名は対象キーボードの実際のパスに置き換えます。プログラムは指定デバイスの物理キー状態を直接読み取るため、端末のフォーカスを外してもSpaceと方向キーの組み合わせが有効です。読み取り権限のある操作専用キーボードを使用してください。ネットワーク設定の優先順位は音声操作と共通です。Whisper・Ollama・ROS 2の起動は不要です。

### ワールドモデルと安全監視

PointCloud2の各フィールドからXYZを復号し、LiDARの取付変換とIMU姿勢で点群を補正します。既知の胴体内部の反射点を除き、姿勢と位置で直近0.4秒の点群を同じ局所座標にそろえます。床面の直接観測と障害物を5cm格子に保持します。障害物点が入った格子は占有扱いとし、床の点だけでは占有を解除しません。

安全監視では停止までに機体外形が通る範囲を、並進と旋回の両方で照合します。初期設定は機体外形80×48cm、停止を見込む時間0.85秒、固定の余裕5cmに加えて測距3.5cm、位置合わせ3cm、格子・スキャン中・履歴のずれの余裕を加えます。これらは実測前の値です。実機の脚の可動範囲、搭載物、通信遅延、制動距離を確認してください。透明物、細い物、低い物体、死角は単一LiDARで検出できるとは限りません。通信断によって停止指令が届かない場合もあります。 [Unitree LiDAR L2仕様](https://oss-global-cdn.unitree.com/static/Unitree%204D%20LiDAR%20L2%20User%20Manual.pdf)

`docs/architecture.md` の構成のうち、点群処理・機体状態監視・ワールドモデル・安全監視・最終判定・送信を実装しています。この操作の入力はキーで、ワールドモデルのメッセージはPythonのデータクラスです。カメラとの融合、経路計画、ROS 2メッセージ化は現時点の実装範囲外です。SDKの指令送信は音声操作と同じ `Robot` に集約しています。 [公式の速度指令サンプル](https://github.com/unitreerobotics/unitree_sdk2_python/blob/master/example/go2/high_level/go2_sport_client.py)

## カメラ映像を取得・表示する

Go2とPCを有線で接続し、PCのGo2側NICに `192.168.123.99/24` などGo2と通信できる未使用のIPv4アドレスを設定してください。NIC名とアドレスは `ip -br -4 addr` で確認できます。プロジェクト直下の `.env` にある `GO2_NET_IF` を利用します。指定の優先順位は `--net-if`、環境変数 `GO2_NET_IF`、プロジェクト直下の `.env`、`192.168.123.0/24` のNICの自動検出です。環境変数を空にすると `.env` を使わず自動検出します。

このPCでは既存の `.venv` を利用できます。映像配信は同梱の公式SDKとCycloneDDSを使用し、`--check` の画像復号やJPEG以外の画像形式の変換には既存のOpenCV・NumPyを使用します。

まず画像を1枚取得・復号して確認します。成功すると解像度とバイト数を表示して終了します。

```bash
cd ~/pyhai_go2_workspace
.venv/bin/python make_code/go2_camera.py --check
```

続けてブラウザへの映像配信を起動します。

```bash
.venv/bin/python make_code/go2_camera.py
```

端末に表示される `http://127.0.0.1:8080/?token=...` をこのPCのブラウザで開いてください。Go2から画像を繰り返し取得してMJPEGとして配信します。ページ内に受信状態やエラーを表示し、受信エラー時は再試行します。終了は端末で `Ctrl+C` です。ロボットの動作指令は送りません。

NICやポートを明示する例：

```bash
.venv/bin/python make_code/go2_camera.py --net-if enx9c69d351a4cf --port 8081
```

別のPCやスマートフォンからは、同じLANにつなぎ、表示URLの `127.0.0.1` を配信PCのLAN側IPに置き換えます。IPは `hostname -I` で確認してください。既定では `0.0.0.0` で待ち受け、URLのトークンが必要です。このPCだけで見る場合は `--host 127.0.0.1` を指定できます。

`Go2用のIPv4アドレスを持つNICを特定できません` と表示された場合は、有線接続・NIC名・IPv4設定を確認してください。`GetImageSample 応答コード` のエラーは、Go2の電源・接続と正しいNICを確認してください。ポートが使用中なら `--port 8081` などに変更できます。

## 初回の配置と依存関係

PCの通常の端末で実行します。

```bash
bash ~/ros_ai_workspace/pyhai_go2_workspace/setup.sh
```

`~/pyhai_go2_workspace` にアプリ、公式SDKのコピー、`.venv` を作成します。既存の `ros_ai` 環境のライブラリを共有するため、新しいパッケージのダウンロードや既存環境の変更は行いません。完全に独立した環境ではないため、`~/miniforge3/envs/ros_ai` は残してください。`requirements.txt` は直接依存、`dependencies.lock.json` は作成時のインストール済み配布パッケージのバージョン一覧です。セットアップでは一覧との一致も検査します。

Whisperの保存済み `base` モデル、Ollamaサーバーと保存済み `qwen2.5:3b` モデルは既存のものを使います。これらはPythonライブラリとは別の依存です。Ollamaは `127.0.0.1:11434` で起動している必要があります。アプリはモデルを自動ダウンロードしません。

## 接続確認

Go2に接続するPC側のネットワークインターフェース名は、このディレクトリの `.env` に保存します。これはデバイスキーではありません。

```dotenv
GO2_NET_IF=enx9c69d351a4cf
```

通常は `--net-if` を省略できます。優先順位は `--net-if`、環境変数 `GO2_NET_IF`、アプリと同じ場所の `.env`、自動検出です。`.env` はGit管理から除外し、設定例は `.env.example` に残しています。

```bash
cd ~/pyhai_go2_workspace
.venv/bin/python go2_voice.py --check
```

APIと運動状態を確認するだけです。停止を含めて動作指令を送りません。自動検出する場合は `.env` の `GO2_NET_IF` を空にし、同名の環境変数も未設定または空にしてください。PCの有線側にはGo2と通信できるIPv4アドレスが必要です。

## 音声操作

```bash
cd ~/pyhai_go2_workspace
.venv/bin/python go2_voice.py
```

Enterを押すと3秒待ってから5秒録音します。「前に進んで」「後ろに下がって」「左に曲がって」「右に曲がって」「止まって」「立ち上がって」「伏せて」のように、1回に1つの動作を話してください。`q` で停止を要求して終了します。リモコンのスティックは中立にしてください。

1回だけ録音する例：

```bash
.venv/bin/python go2_voice.py --once
```

文字で試す例。このコマンドは実際に動作を指示します。

```bash
.venv/bin/python go2_voice.py --text '前に進んで'
```

ロボットへ接続せずにOllamaの分類だけ試す例：

```bash
.venv/bin/python go2_voice.py --dry-run --text '後ろに下がって'
```

マイク一覧：

```bash
.venv/bin/python go2_voice.py --list-devices
```

マイクを指定する場合は `--device 2` のように一覧の番号を指定します。番号は接続状況によって変わります。

## 状態コード100で中断する場合

通常は状態コード0だけを許可します。コード100の意味は未確認であり、正常を示す値とは断定していません。本体とUnitree Goアプリの警告を確認したうえで、この実機の開始時のコード100を個別に許可するには、次を実行してください。

```bash
.venv/bin/python go2_voice.py --check --allow-state-code 100
.venv/bin/python go2_voice.py --allow-state-code 100
```

この指定でも、100以外の非ゼロコードは許可しません。開始時のコード（0または100）を固定し、その後に別の値へ変わった場合は、0への変化も含めて停止します。距離制限・状態の鮮度・数値の検査は引き続き有効です。`--check` は停止を含む動作指令を送信しません。実機での動作確認は必要です。

## 30cm範囲の設定

直進速度は0.15 m/s、通常は1秒です。起動中の前進・後退の指令距離の合計を25cmに制限し、30cmに対して5cmの停止余裕を残します。1回目の指令が15cmなら、2回目は残り10cmまでです。前進後に後退しても、消費した指令距離は戻しません。実際に動かなかった場合も消費します。

Go2の状態値で開始位置からの平面距離を継続監視します。25cmに達したとき、状態受信が0.5秒途切れたとき、またはロボットがエラーコードを通知したときは停止を要求し、その起動中は動作を再開しません。開始位置は自動で取り直しません。再起動すると現在位置が新しい開始位置になります。

旋回は0.2 rad/sで0.5秒です。直進距離の指令枠は消費しませんが、位置の監視は行います。音声認識・Ollamaの処理中や入力待ちにも位置と通信を監視します。終了・例外時は停止を要求します。

**これはソフトウェアによる制限です。物理的に必ず30cm以内で停止する保証はありません。** 位置推定誤差、滑り、制動距離、通信断、リモコンや別プログラムからの指令は制御しきれません。監視もGo2が返す状態に依存します。現場で実際の動きを確認し、必要な場合はリモコンから停止してください。

SDKの `Move` は応答を待たないため、送信成功だけで実際に動いたとは判定しません。指令前後の状態値による位置差を表示します。旋回や移動していない場合も、この表示から実動作を保証するものではありません。

## 初学者向けの読み方

`main` が全体の流れです。`record` が録音、`classify` がOllamaへの問い合わせ、`Robot` がGo2との通信、`SafetyGuard` が距離と状態の検査です。定数はファイルの上部にまとめています。`--help` でオプションを確認できます。

今回の環境では、実機ネットワークやマイクへアクセスできないため、新しい統合ファイルでの音声・実機動作は配置後の確認が必要です。以前のデモで確認できたSDK・モデル・音声入力方式を引き継いでいます。
