# 日本語音声でGo2を操作する

Whisperで音声を日本語のテキストにし、OllamaでGo2への指示に分類します。Pythonが速度と時間を決め、公式SDKのDDS通信でGo2に送信します。WebRTCのデバイスキーは使いません。

自作の実行コードは `go2_voice.py` の1ファイルです。以前のデモやヘルパーファイルは読み込みません。カメラとYOLOは今回の音声操作に不要なので使用しません。

## 初回の配置と依存関係

PCの通常の端末で実行します。

```bash
bash ~/ros_ai_workspace/pyhai_go2_workspace/setup.sh
```

`~/pyhai_go2_workspace` にアプリ、公式SDKのコピー、`.venv` を作成します。既存の `ros_ai` 環境のライブラリを共有するため、新しいパッケージのダウンロードや既存環境の変更は行いません。完全に独立した環境ではないため、`~/miniforge3/envs/ros_ai` は残してください。`requirements.txt` は直接依存、`dependencies.lock.json` は作成時のインストール済み配布パッケージのバージョン一覧です。セットアップでは一覧との一致も検査します。

Whisperの保存済み `base` モデル、Ollamaサーバーと保存済み `qwen2.5:3b` モデルは既存のものを使います。これらはPythonライブラリとは別の依存です。Ollamaは `127.0.0.1:11434` で起動している必要があります。アプリはモデルを自動ダウンロードしません。

## 接続確認

Go2に接続するPC側のネットワークインターフェース名は、このディレクトリの `.env` に保存します。これはデバイスキーではありません。

```dotenv
GO2_NET_IF=enx9c69d351a4cf
```

通常は `--net-if` を省略できます。優先順位は `--net-if`、環境変数 `GO2_NET_IF`、アプリと同じ場所の `.env`、自動検出です。`.env` はGit管理から除外し、設定例は `.env.example` に残しています。

```bash
cd ~/pyhai_go2_workspace
.venv/bin/python go2_voice.py --check
```

APIと運動状態を確認するだけです。停止を含めて動作指令を送りません。自動検出する場合は `.env` の `GO2_NET_IF` を空にし、同名の環境変数も未設定または空にしてください。PCの有線側にはGo2と通信できるIPv4アドレスが必要です。

## 音声操作

```bash
cd ~/pyhai_go2_workspace
.venv/bin/python go2_voice.py
```

Enterを押すと3秒待ってから5秒録音します。「前に進んで」「後ろに下がって」「左に曲がって」「右に曲がって」「止まって」「立ち上がって」「伏せて」のように、1回に1つの動作を話してください。`q` で停止を要求して終了します。リモコンのスティックは中立にしてください。

1回だけ録音する例：

```bash
.venv/bin/python go2_voice.py --once
```

文字で試す例。このコマンドは実際に動作を指示します。

```bash
.venv/bin/python go2_voice.py --text '前に進んで'
```

ロボットへ接続せずにOllamaの分類だけ試す例：

```bash
.venv/bin/python go2_voice.py --dry-run --text '後ろに下がって'
```

マイク一覧：

```bash
.venv/bin/python go2_voice.py --list-devices
```

マイクを指定する場合は `--device 2` のように一覧の番号を指定します。番号は接続状況によって変わります。

## 状態コード100で中断する場合

通常は状態コード0だけを許可します。コード100の意味は未確認であり、正常を示す値とは断定していません。本体とUnitree Goアプリの警告を確認したうえで、この実機の開始時のコード100を個別に許可するには、次を実行してください。

```bash
.venv/bin/python go2_voice.py --check --allow-state-code 100
.venv/bin/python go2_voice.py --allow-state-code 100
```

この指定でも、100以外の非ゼロコードは許可しません。開始時のコード（0または100）を固定し、その後に別の値へ変わった場合は、0への変化も含めて停止します。距離制限・状態の鮮度・数値の検査は引き続き有効です。`--check` は停止を含む動作指令を送信しません。実機での動作確認は必要です。

## 30cm範囲の設定

直進速度は0.15 m/s、通常は1秒です。起動中の前進・後退の指令距離の合計を25cmに制限し、30cmに対して5cmの停止余裕を残します。1回目の指令が15cmなら、2回目は残り10cmまでです。前進後に後退しても、消費した指令距離は戻しません。実際に動かなかった場合も消費します。

Go2の状態値で開始位置からの平面距離を継続監視します。25cmに達したとき、状態受信が0.5秒途切れたとき、またはロボットがエラーコードを通知したときは停止を要求し、その起動中は動作を再開しません。開始位置は自動で取り直しません。再起動すると現在位置が新しい開始位置になります。

旋回は0.2 rad/sで0.5秒です。直進距離の指令枠は消費しませんが、位置の監視は行います。音声認識・Ollamaの処理中や入力待ちにも位置と通信を監視します。終了・例外時は停止を要求します。

**これはソフトウェアによる制限です。物理的に必ず30cm以内で停止する保証はありません。** 位置推定誤差、滑り、制動距離、通信断、リモコンや別プログラムからの指令は制御しきれません。監視もGo2が返す状態に依存します。現場で実際の動きを確認し、必要な場合はリモコンから停止してください。

SDKの `Move` は応答を待たないため、送信成功だけで実際に動いたとは判定しません。指令前後の状態値による位置差を表示します。旋回や移動していない場合も、この表示から実動作を保証するものではありません。

## 初学者向けの読み方

`main` が全体の流れです。`record` が録音、`classify` がOllamaへの問い合わせ、`Robot` がGo2との通信、`SafetyGuard` が距離と状態の検査です。定数はファイルの上部にまとめています。`--help` でオプションを確認できます。

今回の環境では、実機ネットワークやマイクへアクセスできないため、新しい統合ファイルでの音声・実機動作は配置後の確認が必要です。以前のデモで確認できたSDK・モデル・音声入力方式を引き継いでいます。
