現在の到達点

物理キーの押下状態 → 速度候補 → LiDARと機体状態で照合 → 指令の最終判定 → Unitree SDKで送信

模擬点群とモックによる新規・音声回帰テストは前回20件が通過しました。模擬試験では、前方障害物で後退が妨げられないこと、左右の旋回で判定が分かれること、操作中の障害物追加・キー解放・点群途絶で停止処理に入ることを確認しました。既存カメラのテストは検証環境にOpenCVがなく未実施です。 キー操作・点群テスト　音声回帰テスト

実機走行は未検証。 2026年11月11日の調査ではLiDAR点群が約15.4 Hzで受信でき、運動状態コードは 1001 でした。今回のキー操作はコード 0 を要求します。現在のコードと点群は現地で再取得し、取付変換・死角・制動を確認するまで走行判定は保留します。 実機調査記録

変更と意図

変更箇所追加・変更した処理修正の意図
キー入力
go2_teleop.py		Keyboard がLinuxの入力デバイスから押下状態を直接取得。Space と方向キー1つで操作し、送信直前にもう一度読みます。押し始めと解放を検出して、キーを押している間だけ指令を有効にします。組み合わせを1つに絞り、意図しない斜め移動や旋回の同時入力を防ぎます。端末のフォーカスを外しても指定デバイスを読むため、専用キーボードを使います。
速度候補と停止
go2_teleop.py		ManualControl が前後・左右並進を0.08 m/s、左右旋回を0.15 rad/sに固定。停止時は移動中であればゼロ速度と StopMove を送り、キーがすべて離れるまで再開を抑止します。操作を6方向の小さな動きに限定し、障害物が消えたり通信が戻ったりしたときに、押しっぱなしのキーで動き出すことを防ぎます。開始位置からの25 cm制限と、起動中に送る並進指令の累積25 cm制限も適用します。
LiDAR受信
go2_teleop.py／go2_lidar.py		LidarInput がDDSの rt/utlidar/cloud を購読。コールバックは最新点群と受信時の機体状態を渡し、cloud_xyz が PointCloud2 のXYZ位置、型、バイト順、データ長、フレーム名を検査します。既存調査で受信できた経路を使い、古いフレームを順に処理する遅延を抑えます。固定バイト位置や別座標系の誤読で、障害物の左右・高さを取り違えることを防ぎます。 Unitreeの点群表示手順
座標・床面・自機点
go2_lidar.py／設定例		Calibration と pointcloud が取付位置・姿勢、IMU姿勢、機体位置を反映。既知の胴体の衝突形状内部にある点を自機点として数え、残りを床面と占有に分類します。センサーに対する測距を機体の前・左・上に対応づけ、床面や胴体で毎回停止しないようにします。自機除外は胴体内部に絞り、脚は走行時の外形に含めて評価します。設定例のURDF由来の取付値と仮の床面高さは、実測後に採否を決めます。 Go2公式URDF
機体状態と地図の更新
go2_lidar.py		state_monitor が状態コード・姿勢・速度・鮮度を検査。LocalMap が同じ局所座標へそろえた直近0.4秒を5 cm格子に統合します。点群の発行時刻の逆行や位置・向きの急変時は履歴を破棄します。単一フレームの欠落を短い履歴で補いながら、古い床面観測で通行を許可する時間を制限します。床面点は地面を観測した証拠として使い、同じ格子で検出した障害物を床面点だけで消しません。点群と機体状態はPC受信時刻近傍で対応づけています。
方向別の衝突判定
go2_lidar.py		safety_monitor が並進先の長方形と旋回中の外周を判定。80×48 cmの機体外形を0.85秒先まで見込み、固定余裕5 cm、測距3.5 cm、位置合わせ3 cm、格子と時刻ずれの余裕を加えます。壁から離れる操作と壁に近づく操作を区別し、中心がその場に留まる旋回でも角や脚の接触を防ぐ設計です。進行先に観測できていない床があれば保守的に止めます。寸法や余裕は初期値で、実機計測に照らして評価します。
最終判定と送信
go2_voice.py		Robot.final_gate で許可、状態と指令期限を再確認し、command_sender に送信を集約。音声とキー操作が同じLinuxホストで同時に送信しないよう排他を追加し、既存の状態受信にIMU姿勢を含めました。チェック済みの指令だけを送り、処理が遅れて期限を過ぎた速度が実行されるのを防ぎます。停止要求は動作許可が下りない状況でも送信できます。SDKの送信結果と機体が物理的に停止したかは、試験で別々に確認します。 Unitree公式の速度指令例
診断・配置・テスト
README.md／setup.sh／test_go2_teleop.py		--check と --drive を分け、セットアップ先に新規コードと設定例を配置。模擬点群、押下・解放、送信期限のテストを追加しました。実機を動かす前に、座標・受信状態と6方向の可否を診断できるようにします。実機を使わずに再現できる条件を自動テストに残し、現地では校正と実際の制動に集中します。

構成図との差分

構成図の機能今回の扱いと理由
音声・LLMの入力キー操作ではキーの押下状態から固定の速度候補を生成します。入力を離したら止まる条件を、WhisperやOllamaの処理時間から独立させるためです。既存の音声経路には今回のLiDAR判定を接続していません。
カメラ・LiDARの融合fusion に相当する最新観測はLiDAR由来です。まずセンサー1系統で座標・時刻・停止判断を測定しやすくしました。最新の障害物観測を安全判定に反映します。カメラの時刻合わせ、YOLO、異種センサー融合は未実装です。
ワールドモデルのmsgPose・Observation・WorldModel をPythonのデータクラスとして同一プロセス内に保持します。機体状態は検査後に取り込みます。今回の手動操作に必要な点群と姿勢を扱える形に絞ったため、構成図のROS 2メッセージ化、加速度、LLMへの抜粋配信は未実装です。
経路計画と運動制御方向は操作者が選び、制御側はその速度候補を通すか停止するかを判断します。障害物を避ける別経路の提案、速度のなめらかな制御、停止完了の自動判定は今回の実装に含みません。

構成図は参照資料として扱い、更新は行っていません。 システム構成図と設計上の制約

実機試験の実行手順

UbuntuのBashで、番号順にコードブロックを1つずつ実行します。設置・キー操作・合否確認が書いてあるところでは、コマンドを止めてその作業を行います。01〜05は機体を動かさずに実施します。06以降は、状態コード0、取付校正、対象方向の判定、リモコンでの停止操作を確認した場合に進みます。

準備 → 通信 → 校正 → 静止診断 → キー操作 → 制動計測 → 障害物停止 → 25 cm制限 → 受信異常 → 終了・競合

01　作業場所・接続・ログの準備

  1. 平坦で滑りにくい床を選び、ケーブルを脚の通り道から外します。Go2を立位にし、公式アプリの警告、機種とファームウェアを記録します。操作者とは別にリモコンを持つ停止担当を決め、停止操作を静止状態で確認します。
  2. Ubuntuの端末Aで次を実行します。配置先が異なる場合は、最初の行を go2_teleop.py がある場所に置き換えます。ls で3つとも表示されたら進みます。 配置と依存環境
cd "$HOME/pyhai_go2_workspace"
ls -l .venv/bin/python go2_teleop.py docs/go2_lidar_calibration.example.json
ip -br -4 addr

出力の中からGo2の有線側インターフェースを選びます。次のブロックの最初の入力欄へ、そのインターフェース名を貼り付けます。以降は同じ端末Aを使います。

read -r -p 'Go2に接続した有線NICの名前: ' GO2_TEST_NIC
ip -4 addr show dev "$GO2_TEST_NIC"
GO2_TEST_CAL="$PWD/go2_lidar_calibration.json"
GO2_TEST_LOG=$(mktemp -d "$PWD/go2-test-$(date +%Y%m%d-%H%M%S)-XXXXXX")
if [[ ! -e "$GO2_TEST_CAL" ]]; then
  cp docs/go2_lidar_calibration.example.json "$GO2_TEST_CAL"
fi
printf '作業場所 %s\n校正ファイル %s\nログ保存先 %s\n' "$PWD" "$GO2_TEST_CAL" "$GO2_TEST_LOG"

go2_check() {
  local label="$1" rc log
  log=$(mktemp --suffix=.log "$GO2_TEST_LOG/$label-XXXXXX") || return
  printf '保存先 %s\n' "$log"
  .venv/bin/python -u go2_teleop.py --check --net-if "$GO2_TEST_NIC" \
    --calibration "$GO2_TEST_CAL" 2>&1 | tee "$log"
  rc=${PIPESTATUS[0]}
  printf '終了コード %s\n' "$rc" | tee -a "$log"
  return "$rc"
}

進む条件。 指定NICにGo2と通信できるIPv4アドレスがあり、表示されたログ保存先が存在すること。設定例からコピーした取付値と床面高さは03で照合します。

02　動作指令を送らずに通信を確認

go2_check 02-first
for n in 1 2 3; do
  go2_check "02-repeat-$n" || break
  sleep 1
done

期待する出力。 運動状態コード 0、点群受信 'utlidar_lidar'、点群更新成功 と6方向の結果。診断の終了コード0は地図の更新を示します。方向ごとの可否は、その行の表示で判断します。

  • 1001 など非ゼロが出たら走行試験を保留し、本体と公式アプリを確認します。点群を受信できていても、この状態で移動は許可されません。
  • 点群は受信したものの床面不足で更新できない場合は03で校正し、02をやり直します。点群自体が届かない場合はNICと有線接続を確認します。
  • ソース一式を配置していて受信頻度も記録したい場合は、次を実行します。JSONの各トピックにある count と approx_hz が確認対象です。--check は鮮度超過や発行時刻異常を拒否します。各サンプルの受信間隔の最大値が必要な場合は、読み取り専用のDDS購読ログを別途採取します。 受信確認ツール
if [[ -f tools/physical_ai/check_go2_sensors.py ]]; then

03　取付変換を確認し、床面高さを入力する

  1. 床に機体原点の真下と、前・左の向きをテープで示します。立位で床から機体原点までの高さを測り、その値をメートルにして負号を付けたものを ground_z_m に入れます。例えば高さ32 cmなら -0.32 です。
  2. 機体原点から既知の距離に板を1枚ずつ置き、前・後・左・右を比較します。点群を機体座標に変換して確認できる環境では、前が+X、左が+Y、上が+Zで、板の位置と計測値が整合することを確認します。RVizの固定フレームを utlidar_lidar にした表示はセンサー座標です。機体座標の照合には別途取付変換を適用します。 Unitreeの点群表示手順
  3. 取付位置 lidar_xyz_m と取付姿勢 lidar_rpy_rad を確認し、必要に応じて編集します。板を撤去してから go2_check 03-calibrated を実行します。設定値と、床面・板の位置残差を記録します。 設定例
nano "$GO2_TEST_CAL"
.venv/bin/python -m json.tool "$GO2_TEST_CAL"
go2_check 03-calibrated
cp "$GO2_TEST_CAL" "$GO2_TEST_LOG/calibration-used.json"

nano では Ctrl＋O、Enter で保存し、Ctrl＋X で戻ります。構文検査はJSONの形式を検証します。取付の合否は実測位置との照合で判定します。

RVizの utlidar_lidar 座標で板上の点を選べる場合は、表示されたXYZをメートルで入力すると、設定ファイルの取付変換を適用した機体座標を確認できます。水平で静止した状態で、実測した符号と距離に照らし合わせます。

read -r -p '板上の点のセンサー座標 X Y Z (m、空白区切り): ' GO2_X GO2_Y GO2_Z
.venv/bin/python - "$GO2_TEST_CAL" "$GO2_X" "$GO2_Y" "$GO2_Z" <<'PY'
from pathlib import Path
import sys
from go2_lidar import Calibration

calibration = Calibration.load(Path(sys.argv[1]))
point = tuple(map(float, sys.argv[2:]))
body = [origin + sum(a * b for a, b in zip(row, point))
        for row, origin in zip(calibration.matrix, calibration.xyz)]
print('機体座標 [m]  X前 {:+.3f}  Y左 {:+.3f}  Z上 {:+.3f}'.format(*body))
PY

04〜05　障害物の位置だけを変え、静止診断を比較する

機体は立位静止のままにします。下のループは配置ごとに入力待ちになります。配置が終わり全員がセンサーの前から離れたら、端末Aで Enter を押してください。板を交換するたびに、直前の板は撤去します。

for placement in empty front rear left right front-left front-right; do
  read -r -p "配置 $placement を準備したら Enter: " GO2_TEST_READY
  go2_check "05-$placement"
done
配置板の位置見る行
empty板を外し、周囲の床が見える状態にする。6方向の基準結果を記録。未観測が出た方向は保留。
front / rear板の面を機体に向け、前または後ろの中央に置く。開始目安は機体原点から約55 cm。板は外形や脚から離す。前の板は前進、後ろの板は後退の行で 障害物があります。反対側は床が観測できる場合に許可。
left / right板を左または右の中央に置く。開始目安は機体原点から約38 cm。板の側への並進が拒否される。反対側との違いを記録。
front-left / front-right板を前角の斜め外側に置く。位置を少しずつ変え、左右それぞれの判定を比べる。機体の角が近づく旋回を拒否。左右とも拒否された場合は判定理由を確認し、板の位置と未観測域を分けて調べる。

板で確認した後、細い棒・低い段差相当の物・暗色や透明の物を1つずつ同じ場所に置きます。下のラベルを材質と方向が分かる名前に変えて繰り返し、検出できなかった位置を記録します。脚や搭載物が遮る領域も確認します。 Unitree LiDAR L2仕様

go2_check 04-thin-pole-front

進む条件。 開けた床で対象方向が許可され、同じ方向の通過範囲に板を置くと障害物で拒否されること。板を検出できない、または未観測が続く方向は実走を保留します。配置距離は初回の目安なので、実際に測った値をログに対応づけます。

06　6方向とキー解放を確認する

板と人を試験区域から出し、床に機体原点の開始位置と向きをテープで示します。停止担当はリモコンを持ちます。次を端末Aに貼り付け、一覧から操作用キーボードのデバイスパスを入力します。

ls -l /dev/input/by-id/*-event-kbd
read -r -p '操作用キーボードのデバイスパス: ' GO2_TEST_KBD
test -c "$GO2_TEST_KBD" && test -r "$GO2_TEST_KBD" \
  && echo 'キーボード読取可' || echo 'デバイスパスまたは読取権限を確認'

go2_drive() {
  local label="$1" rc log
  log=$(mktemp --suffix=.log "$GO2_TEST_LOG/$label-XXXXXX") || return
  printf '保存先 %s\n' "$log"
  .venv/bin/python -u go2_teleop.py --drive --net-if "$GO2_TEST_NIC" \
    --calibration "$GO2_TEST_CAL" --keyboard "$GO2_TEST_KBD" \
    2>&1 | tee "$log"
  rc=${PIPESTATUS[0]}
  printf '終了コード %s\n' "$rc" | tee -a "$log"
  return "$rc"
}

端末Aで「キーボード読取可」が出たら、試験ごとに go2_drive を起動します。プログラムが 待機。Spaceと方向キーを押すと移動します。 と表示してから操作します。指定デバイスを直接読むため、方向操作は端末のフォーカスに依存しません。

go2_drive 06-keys
  1. 無入力 → W だけ → Space だけ → Space＋W＋D の順で試します。各操作の間で全キーを離します。どれも動かなければ合格です。
  2. 静止診断で許可された方向だけ、Space と W、S、A、D、Q、E を1方向ずつ短く押します。表示と実際の前進・後退・左並進・右並進・左旋回・右旋回を照合します。試行のたびに両キーを離し、機体の停止を待ちます。
  3. 安全に動ける方向で、方向キーだけを離す試行とSpaceだけを離す試行を1回ずつ行います。残したキーを押し続けても停止し、両方を離してから押し直した場合にだけ再開すれば合格です。
  4. Esc で終了します。位置や累積指令の上限が先に出た場合は結果を記録し、機体が停止していることを確認して、残りの方向を別起動で試します。

07　解放から停止までの時間・余走・旋回角を測る

方向ごとに次を実行します。ラベルには forward、rear、left などを入力します。正常に停止してから Esc で終了し、別の方向へ進みます。

read -r -p '今回の計測方向のラベル: ' GO2_TEST_DIRECTION
go2_drive "07-$GO2_TEST_DIRECTION"
  1. 床に目盛りを置き、キーを離す瞬間と機体の動きが同じ動画に入るように撮影します。方向ごとに短い動きから始め、機体が安定して停止したことを確認して3回繰り返します。
  2. 動画で「キーを離したフレーム」と「機体が静止したフレーム」を読みます。フレーム差を撮影fpsで割って停止時間を求めます。同じ2フレームの機体位置・向きの差を、余走距離と余分に回った角度として記録します。脚が胴体より外に出る最大位置も測ります。
  3. 各方向の最大値を判定に使います。進む条件は、計測誤差を含めて停止時間が0.85秒の見込みに収まり、余走距離・旋回角・脚の張り出しが設定した停止範囲と外形の余裕に収まることです。判定できない場合は障害物に向けた試験を保留します。

08　柔らかい障害物の手前で止まることを確認する

05と07で確認できた方向に限り、05で障害物を検出した位置に柔らかい板を置きます。機体や脚との間にはすき間を取ります。旋回では機体の角が近づく側に置きます。置き直すときは運転を Esc で終了してから作業します。

read -r -p '障害物に向けて試す方向のラベル: ' GO2_TEST_DIRECTION
go2_check "08-$GO2_TEST_DIRECTION-detect-target"

対象方向が障害物で拒否されれば、柔らかい板を検出できています。板を機体から遠ざけ、予定した開始配置で再診断します。

go2_check "08-$GO2_TEST_DIRECTION-before-drive"

開始配置で対象方向が許可された場合に、以下のブロックを実行します。拒否された場合は理由を記録し、板の位置と未観測域を見直します。

go2_drive "08-$GO2_TEST_DIRECTION"
  1. 板に向かって短く操作します。停止担当は最小すき間を割りそうな場合にリモコンで止めます。既存の25 cm制限が先に効いた場合は、その結果を記録し「障害物停止」は未実施とします。
  2. 障害物があります で止まったら、キー保持で再始動しないことを確認し、全キーを離して Esc で終了します。静止した機体の脚または外装と板の最も近い部分を測ります。接触なし・すき間5 cm以上が初回試験の基準案です。旋回は角や脚の最接近も動画で確認します。

09　開始位置と累積並進指令の25 cm制限を分けて確認する

  1. 障害物を撤去し、開始点をテープで示します。go2_drive 09-origin-limit を起動し、許可された直進方向のキーを保持します。停止見込み位置が開始位置から25cmの範囲を超えます。 が出た時点で最後の移動方向と実際の停止位置を記録し、終了します。
  2. 静止後、別起動で go2_drive 09-command-budget を実行します。前進と後退が許可される場所で、短い前進・停止・短い後退・停止を繰り返します。移動のたびに両キーを離し、完全に停止してから逆方向へ入れます。
  3. 開始点の近くでも この起動中の並進指令が合計25cmに達しました。 が出れば累積制限を確認できています。距離枠は前進・後退で相殺されません。25 cmは指令と位置判定の基準値です。実際の余走は07の値と合わせて記録します。

ソース一式の作業場所なら、先に次を実行できます。このコマンドは模擬入力だけを使います。試験ファイルがない配置先では、ソース側へ移動して実行します。
